## Procedure

### Step 1: Solve it yourself first

Using only the stem and any code in it, work out the correct answer before looking at which choice is marked correct. Trace code line by line and track every variable. Write down your answer.

### Step 2: Check the key

Compare your answer with the choice marked correct. If they differ, re-trace carefully before concluding the key is wrong. Then evaluate every other choice against the stem AS WRITTEN and confirm each one is actually incorrect.

### Step 3: Compare the choices with each other

Write one line per choice stating exactly what it evaluates to, prints, or does under the conditions in the stem (for example "true exactly when x is odd", "prints 6", "skips the last element"). Then compare every pair of lines, including pairs of wrong choices. If two lines describe the same result or behavior, those two choices are equivalent. That is an error even when both choices are wrong, because a student who rules out one can rule out the other for free.

### Step 4: Checklist

Report a finding only for a concrete defect. Do not report style preferences, wording you would merely phrase differently, or a question that is simply easier or harder than you would make it.

Errors (the question is wrong or unfair):
- the marked answer is incorrect, or more than one choice is correct
- two choices are identical or equivalent (same value, same output, or code that behaves the same way under the conditions in the stem)
- the stem refers to a method, class, table, or data set that is not shown
- the Java code does not compile, unless the question is about the compile error
- a factual statement about Java behavior is wrong
- the question-level explanation disagrees with the marked answer or contains a calculation error

Warnings (worth fixing):
- something gives the answer away: a method or variable name that states the result or the property being tested (e.g. `countEvens`, `isSorted`, `result7`), a comment that performs part of the student's reasoning (e.g. `// x becomes 7`), wording that only fits one choice, or a correct choice that stands out by length or form
- a choice's explanation does not match that choice, or does not identify a real misconception
- an explanation refers to choices by letter or position ("A", "the first option"); choices are shuffled when shown
- inline code is not in backticks, or a Java code block is not fenced as `java`
- choices are code but laid out as one-line inline code instead of fenced multi-line `java` blocks

A contextual comment such as `// ASCII value 65` that only supplies background is acceptable.

## Fix Rules

If there are errors or warnings that can be fixed, write a revised question.

- Change as little as possible. Keep the code, wording, and formatting of every part that is fine.
- Never move the correct answer to a different choice: copy every `is_correct` value exactly as it is in the question under review. If the key is wrong, rewrite the TEXT of the choice marked correct so it becomes the correct answer, and update its explanation. This holds even when the right answer already appears as another choice.
- If that rewritten choice is now the same as or equivalent to another choice, replace that other choice with a new plausible wrong answer based on a specific misconception, and update its explanation.
- To remove a giveaway name, rename it consistently everywhere it appears (stem, choices, explanations).
- Keep the same number of choices.
- Update the question-level explanation so it agrees with the revised question.
- After revising, check the whole revised question again: exactly one correct choice, no two choices equivalent, code compiles, explanations agree.
